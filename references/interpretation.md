# 判读手册

`analyze.py` 的阈值是怎么定的，什么情况下不适用，误判了怎么办。

## 核心原则

模型输出长度本身就是随机变量。**单次长短没有信息量，只有同一任务、同一模型、同条件下的重复抽样才有。**

抽样单位不是「一次回答」，而是「一组三次」。三次以下不下结论。

## 阈值表

| 指标 | 阈值 | 含义 |
|---|---|---|
| 轮间波动率 `(max-min)/mean` | < 15% | 稳定 |
| 同上 | 15% – 35% | 正常采样波动 |
| 同上 | > 35% | 疑似降级，需延长到 5 轮确认 |
| 末轮 / 首轮 | < 60% | 疑似递降，优先怀疑弱模型分流 |
| 平均字符数 | < 200 | 需先确认是否执行型模式，再判定降级 |
| 结构要素 | 分点数、代码块、标题数同步下降 | 降级的强信号，比长度更可靠 |

**为什么结构要素比长度更可靠：** 长度受话题和心情影响，但「该分点的地方不分点、该给代码的地方只给描述」是能力变化，不是风格变化。

## 三类结论的区分标准

### 一、模型定位差异（不是降级）

特征：
- 换了模式后立刻变化，切换回原模式即恢复
- 输出更短，但**结构完整、任务完成度没下降**
- 不再解释过程，只给结果

典型案例：Codex 模式 vs 聊天模式。Codex 被设计成工程执行型——少说话、直接给命令和代码。用它聊天会觉得「变笨」，实际是分工不同。

**处置：什么都不用做。** 需要讨论就用聊天模式，需要动手就用 Codex 模式。

### 二、正常采样波动（不是降级）

特征：
- 三次长度有起伏，但都落在合理区间
- 结构要素稳定，任务完成度一致
- 换时段重测结果回到正常范围

**处置：观察即可。**

### 三、真实降级

按发生层分三种，处置完全不同：

| 层级 | 信号 | 处置 |
|---|---|---|
| 额度层 | 命中 `usage limit` / `rate limit` / 「稍后再试」 | 额度耗尽被切轻量模型。等额度恢复重测，核对订阅状态 |
| 路由层 | 持续变短、结构丢失、模型标识变化 | 可能被 A/B 分到弱模型。换时段、换节点重测，多次复现再行动 |
| 账号层 | 多任务同时劣化且伴随异常提示 | 风控降级。检查账号状态与登录环境一致性 |

## 不适用场景

以下情况这套方法测不出来，别硬套：

- **只做了一次回答**：一条数据没有波动率，无法判读
- **跨模式比较**：聊天模式 vs Codex 模式的长度差属于定位差异，不是降级
- **跨模型比较**：gpt-5 vs gpt-5-mini 比长度，比的是产品分层，不是降级
- **任务本身无确定结构**：闲聊、头脑风暴类问题长度天然波动大，改用有明确交付物的任务
- **网络不通的情况下**：先解决连通性。403 和超时都不是模型问题

## 误判后怎么纠

如果按「疑似降级」下了结论，但用户实际感受没变差，检查两件事：

1. **任务是否区分度足够**：三次回答都很短且都完整 → 任务太简单，换更复杂的任务
2. **是否混入了不同条件**：中途切模式、换节点、改参数，任一项发生则该组数据作废

## 和网络诊断的分工

| 现象 | 该用哪个技能 |
|---|---|
| 打不开、转圈、卡加载页、报 403 | `proxy-openai-diagnosis` |
| 能正常用，但觉得回答质量下降 | `codex-model-degradation-check`（本技能） |

两者不重叠。先确认能连上，再谈质量。
